# 实施待确认问题

本文只记录权威规格尚未给出、实现不能自行猜测的业务参数；不改变现有需求。

## Phase 1

1. 配送员分成要求按“业务类型 / 收益来源”配置，但规格未给出任何默认比例。V1 当前会预建固定六业务与固定收益来源的配置行，比例保持未配置（空值），由管理员明确填写；后续产生收益前必须拒绝使用未配置比例。请确认默认比例后再补入数据迁移或配置默认值。

## Phase 3

1. 快递强重复提醒要求“同一收件归属 + pickup_area + normalized pickup_identifier + 时间窗口”，但规格没有给出窗口长度。当前实现保守地以同一 `service_date` 作为窗口；原值仍保留，规范化值仅用于比对，命中后允许录单员明确确认并继续创建。若需跨日小时窗口，请补充准确时长和边界算法。
