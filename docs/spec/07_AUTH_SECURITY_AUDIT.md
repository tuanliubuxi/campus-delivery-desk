# 07. 认证、安全、权限与审计

## 1. 认证

使用 Django Session + HttpOnly Cookie。

密码由系统生成随机口令交给用户，数据库只存 Argon2/PBKDF2 等安全哈希。不开公开注册，不要求首次改密，不做失败登录限流。

## 2. 单账号单活跃会话

使用 ActiveLoginLease，而不是简单 `online=true`。

建议参数：heartbeat 30s，stale timeout 150s。

登录：fresh lease → 拒绝；stale → revoke 后允许新登录。

心跳必须校验 session 与 lease token 绑定。

关闭标签时 `sendBeacon` 可尝试 logout/release，但不能依赖成功。

管理员可强制下线；停用账号和重置密码也应使现有 Session/lease 失效。

## 3. 角色权限

### 管理员

全局管理、配置、用户、备份、恢复、维护、经营/工资、任何结算撤销。

### 录单员

录单、客户/代理、结算、异常、人工费用调整、补录；不能改系统级配置/账号。

### 配送员

只能处理自己相关任务、归拢、异常、个人统计；不能访问团队经营金额、工资总表和客户库管理。

## 4. 关键权限规则

- 前端角色选择不是权限来源。
- Service 也要校验权限，不只 View。
- 代理客户临时信息只对相关配送任务展示必要字段。
- 配送员不能确认客户收款。
- 配送员不能直接写 ChargeItem 总价。

## 5. CSRF/XSS/文件安全

- Django CSRF 保持开启；
- 用户自由文本模板默认 autoescape；
- 图片检查真实格式，不信任 MIME/扩展名；
- media 不使用可猜的公开静态目录直接暴露，走权限下载 endpoint；
- 删除 EXIF/GPS；
- 文件名内部随机化。

## 6. 审计事件

必须记录：

- 登录/退出/强制下线；
- 创建/修改/取消/补录订单；
- 接单、取件、转单、完成；
- 归拢；
- 异常与处理；
- 费用项新增/作废（未结算前也需留操作）；
- 结算/撤销/退款；
- 代理批次创建/结算；
- 配置修改；
- 备份/恢复/维护；
- 图片清理。

AuditEvent append-only。

## 7. 备注体系

区分：客户长期备注、本单备注、配送备注、归拢备注、异常说明、人工处理说明、代理批次/临时收件人备注。

普通备注修改需留 diff；异常/财务记录不得无痕删除。
