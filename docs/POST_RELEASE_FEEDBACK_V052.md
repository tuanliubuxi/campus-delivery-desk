# v0.5.1 发布后的反馈与定案（v0.5.2）

电脑浏览器经 cpolar 访问失败的问题已由用户自行解决，不纳入本轮修改。

| 用户提出的问题 | 分析建议 | 用户反馈／本轮定案 |
| --- | --- | --- |
| 计薪比例数字选择器不适合；精度应为两位小数 | 比例独立于正整数选择器，前后端统一校验 | 输入 **0.00～1.00（含端点）**，最多两位小数；`0.75` 表示 75%，不是输入 75；默认与个人比例一致，历史快照不静默改写 |
| 检查登录历史分页跳转 | 复核共用页码组件和超过一页的真实页码 | 保留首页／尾页／页码输入／跳转及弹框内翻页，增加回归测试 |
| 确认核算后缺返回列表入口 | 嵌入明细隐藏了普通页面返回链接 | 工作台弹框内明确“返回待核算与待发放列表”，刷新后尽量保留位置 |
| 代理批次页面滚动不顺，三层滚动与标题被遮挡 | 批次优先，代理人移入弹框；批次详情取消收件人内层纵向滚动 | 主页面显示批次；代理人弹框内单一有界列表；批次按进行中／待结算、已结算、已取消切换并分页 |
| 临时收件人快递录入不显示“添加快递” | 代理入口漏传共享组件数据且仍按单件提交 | 与普通录单共用多件校验及原子创建；每件保持独立订单并归属本批次临时收件人 |
| 整批取消常驻表单不合适 | 角落按钮开启原因确认弹框，后端复核可取消状态 | 必填原因、确认和返回按钮；不满足规则时不允许整批取消 |
| 整批取消报 500 | 日志指向 SQLite `database is locked`；整笔事务短重试并给可读错误 | 有界重试；最终失败时提示数据库忙、不留下部分取消；不以延长超时掩盖问题 |
| 代理人卡片“批次：X”含糊 | 状态汇总及适配主题的指示灯，文字不能省 | 显示总数、录入中、待结算、已结算、已取消 |
| 所有长列表是否都需要序号 | 有稳定排序的分页表格可加；卡片、嵌套物件和业务编号足够清晰的列表不强加 | 同意按列表性质选择；序号代表当前筛选顺序，跨页按起始行计算，不作为业务 ID |
| 添加物件后关闭弹框，页面位置大幅变化 | 局部变化以操作按钮作锚点；同页刷新一次性恢复位置；新目的页不强留旧坐标 | 推广到弹框关闭引起内容变化的流程，移动端重点验证 |
| 页面与限高列表同时可滚，手机易误滑 | 列表加主题底色及边界，窄屏两侧留出滑动页面的空间，避免纵向滚动嵌套 | 保留分页和限高；宽窄屏均区分页面与列表的滚动区域 |
| 展开凭证原始图片后，只有弹框边缘容易滚动 | 凭证图片、证据列表与弹框的多层纵向滚动互相截获手势 | 默认仅弹框主体纵向滚动，图片允许单指平移页面和双指缩放；同类预览区一并检查 |

验收时还需分别在桌面滚轮与手机触摸下检查弹框背景锁定、滚动边缘和焦点回归。
